MCP Server 开发简单教程（虚拟环境版）

本教程基于一个真实的最小示例，带你在虚拟环境中从零实现、测试并在 Trae IDE 中注册一个 MCP Server。示例服务器名为 clock，只提供一个工具 get_current_time——返回真实系统时间。

使用虚拟环境的好处：依赖隔离、不污染全局 Python、项目可移植。

1. 环境准备（虚拟环境）

前提：Python 3.10+（本教程使用 3.14）。

1.1 创建项目目录

先建一个专门的项目文件夹，后续所有文件（虚拟环境、服务器脚本、依赖清单）都放在里面：

mkdir first-mcp-server
cd first-mcp-server

1.2 创建虚拟环境

在项目目录下执行：

python -m venv .venv

会生成一个 .venv 文件夹，里面是独立的 Python 解释器和包目录。

1.3 激活虚拟环境

.venv\Scripts\activate.bat

激活成功后命令行前面会出现 (.venv) 前缀，此时 python / pip 都指向虚拟环境。

提示：cmd 下用 activate.bat 激活，不受 PowerShell 脚本执行策略的限制。也可以干脆不激活，全程用绝对路径调用 .venv\Scripts\python.exe（见后文）。

1.4 安装依赖

在项目里放一个 requirements.txt：

mcp>=1.2.0

然后在激活状态下安装：

pip install -r requirements.txt

依赖会装进 .venv，不影响全局环境。

2. 编写服务器

新建 clock_server.py：

from datetime import datetime

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("clock")


@mcp.tool()
def get_current_time() -> str:
    """返回当前的真实系统时间，格式为 YYYY-MM-DD HH:MM:SS。"""
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")


if __name__ == "__main__":
    mcp.run()

要点：

  • FastMCP("clock") 创建一个服务器，"clock" 是它的名字。
  • @mcp.tool() 装饰的函数会自动变成一个工具。
  • 函数的类型标注（-> str）用于自动生成输出类型，参数类型标注用于生成输入参数校验。
  • docstring 会作为工具描述提供给模型，让模型知道何时该调用它——所以要写清楚。
  • mcp.run() 默认使用 stdio 传输：通过标准输入输出以 JSON-RPC 通信，是本地运行最常见的方式。

3. 编写测试客户端（可选但推荐）

直接运行服务器会进入等待输入状态，不方便验证。写一个客户端来自动连接并调用工具。新建 test_client.py：

import asyncio

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client


async def main() -> None:
    params = StdioServerParameters(command="python", args=["clock_server.py"])
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()

            tools = await session.list_tools()
            print("tools:", [t.name for t in tools.tools])

            now = await session.call_tool("get_current_time", {})
            print("get_current_time() =", now.content[0].text)


if __name__ == "__main__":
    asyncio.run(main())

要点：

  • stdio_client 会以子进程方式启动服务器（相当于替你运行 python clock_server.py）。因为测试客户端本身在激活的 venv 中运行，这里的 command="python" 用的就是 venv 的解释器。
  • session.initialize() 完成协议握手。
  • list_tools() 拉取服务器暴露的工具列表。
  • call_tool(name, args) 调用某个工具，无参数时传 {}。

4. 运行测试

确保虚拟环境已激活（命令行有 (.venv) 前缀），然后：

python test_client.py

预期输出：

tools: ['get_current_time']
get_current_time() = 2026-07-01 10:12:07

看到工具列表和真实时间，说明服务器工作正常。

未激活 venv 时，也可以用绝对路径直接跑： 

.venv\Scripts\python.exe test_client.py

5. 在 Trae IDE 中注册（关键：指向 venv 的 python）

Trae 会以子进程方式启动 MCP Server，它不会自动激活你的虚拟环境。因此 command 必须指向虚拟环境里 python 的绝对路径，否则会因为找不到 mcp 包而启动失败。

  1. 打开右侧 AI 对话面板，进入 MCP 管理页面。
  2. 点击 添加 MCP Servers → 选择 手动配置 / 导入 JSON。
  3. 粘贴以下配置并保存：
{
  "mcpServers": {
    "clock": {
      "command": "c:\\ws\\mcp-learn\\first-mcp-server\\.venv\\Scripts\\python.exe",
      "args": ["c:\\ws\\mcp-learn\\first-mcp-server\\clock_server.py"]
    }
  }
}

注意事项：

  • command 用 venv 里的 python 绝对路径（.venv\Scripts\python.exe），这等价于「用虚拟环境的解释器跑脚本」，依赖自然就在。
  • args 里的脚本路径同样用绝对路径，Windows 下反斜杠写成 \\。
  • 列表里出现 clock 且状态为已连接（绿色），即注册成功。

附录一：什么是 MCP

MCP（Model Context Protocol，模型上下文协议）是一个开放协议，用于把「外部能力」标准化地暴露给大模型。模型本身有几个天然做不到的事：

类别 为什么模型做不到 工具示例
实时信息 有知识截止，不知道「现在」 当前时间、天气、汇率
本地系统访问 访问不了你的电脑 读本地文件、列目录
确定性精确计算 会算错 / 靠猜 哈希、大数运算
真随机 / 副作用 只能生成文本，不能真执行 生成 UUID、写文件、发请求

MCP Server 就是把这些能力封装成「工具（tool）」，模型通过协议调用它们。

附录二：Python MCP SDK 简介

官方包名为 mcp（pip install mcp），既含服务端也含客户端。其中 FastMCP 是最常用的服务端高层封装，用装饰器几行代码就能搭一个服务器。

A. FastMCP 服务端

创建服务器

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("服务器名字")

三种可暴露的能力

能力 装饰器 作用 类比
工具 Tool @mcp.tool() 让模型执行动作、调用函数 POST 接口
资源 Resource @mcp.resource("uri") 让模型读取数据 GET 接口
提示词 Prompt @mcp.prompt() 提供可复用的提示词模板 模板

工具示例（带参数）

@mcp.tool()
def add(a: float, b: float) -> float:
    """将两个数相加并返回和。"""
    return a + b
  • 参数和返回值的类型标注会自动转成 JSON Schema，供模型理解与校验。
  • docstring 作为工具说明。写清楚「做什么、什么时候用」能显著提升模型的调用准确率。
  • 抛出异常即代表工具出错，客户端会收到 isError=True 的结果。

资源示例

@mcp.resource("config://app")
def get_config() -> str:
    """返回应用配置。"""
    return "some config data"

提示词示例

@mcp.prompt()
def review(code: str) -> str:
    """生成代码审查提示词。"""
    return f"请审查这段代码：\n\n{code}"

启动与传输方式

if __name__ == "__main__":
    mcp.run()                      # 默认 stdio（本地、最常用）
    # mcp.run(transport="sse")     # HTTP/SSE，供远程或浏览器访问
  • stdio：通过标准输入输出通信，适合被 IDE / 桌面客户端以子进程拉起。
  • SSE / Streamable HTTP：以 HTTP 服务形式运行，适合远程访问。

B. 客户端常用 API

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client
调用 说明
StdioServerParameters(command, args) 描述如何以子进程启动服务器
stdio_client(params) 建立 stdio 连接，返回 (read, write) 流
ClientSession(read, write) 会话对象，管理一次连接
await session.initialize() 协议握手，必须最先调用
await session.list_tools() 列出所有工具
await session.call_tool(name, args) 调用工具，args 是参数字典
await session.list_resources() 列出资源
await session.read_resource(uri) 读取某个资源
await session.list_prompts() 列出提示词
await session.get_prompt(name, args) 获取渲染后的提示词

返回结果的读取：call_tool 返回的对象里，.content 是一个列表，文本结果取 .content[0].text；出错时 .isError 为 True。

C. 关键约定小结

  • 一个函数 + 类型标注 + docstring + @mcp.tool() = 一个新能力。
  • 类型标注决定输入/输出 schema，docstring 决定模型「何时调用」。
  • stdio 是本地默认传输；被 IDE 启动时记得让解释器指向正确的（虚拟）环境。
  • 客户端调用顺序固定：连接 → initialize → list_* / call_*。
